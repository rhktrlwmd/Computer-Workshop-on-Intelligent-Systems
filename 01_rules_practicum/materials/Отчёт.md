# Экспертная система подбора книг

Дисциплина: Компьютерный практикум по интеллектуальным системам (02.03.02)

Практические упражнения по представлению знаний и логическому выводу

Вариант 3. Выбор книги на основе предпочтений читателя

## 1 Цель и постановка задачи

Разработана учебная экспертная система, которая получает предпочтения читателя, выводит подходящие жанры и книги, а затем выбирает одну рекомендацию по заданной стратегии. Система объясняет результат через последовательность применённых правил и дерево доказательства.

Работа включает три части. В первой сформирована база знаний из продукционных правил и определены исходные факты. Во второй реализованы прямой и обратный вывод. В третьей добавлено разрешение конфликтов и выполнен запуск той же базы знаний в CLIPS через библиотеку clipspy.

| Часть | Результат |
|---|---|
| Представление знаний | 7 входных признаков, 3 промежуточных признака, 6 книг, 12 правил |
| Логический вывод | Прямой вывод до завершения и независимый обратный поиск доказательства |
| Конфликты и фреймворк | Приоритет, специфичность, порядок правил и реализация в CLIPS |
| Проверка | 9 демонстрационных примеров и 30 автоматических тестов |

## 2 Устройство системы

База знаний хранит общие правила для всех читателей. Рабочая память содержит факты одного запуска: сначала ответы читателя, затем результаты применения правил. Механизм вывода сопоставляет условия правил с фактами. Механизм объяснения сохраняет шаги вывода и доказательства целей.

Исходные факты, промежуточные жанры и книги представлены строковыми атомами. Например, likes_science означает интерес к науке, genre_sf означает подходящую научную фантастику, а candidate:martian означает, что «Марсианин» входит в число кандидатов.

Рекомендации и числовые приоритеты заданы как учебные экспертные предположения. Они служат для демонстрации алгоритмов. Приоритет 60 не означает вероятность 60 процентов.

## 3 Факты и рабочая память

Пользователь отвечает «да» или «нет» на семь вопросов. Положительный ответ добавляет соответствующий факт в рабочую память. Пропущенный признак или ответ «нет» не добавляет положительного факта. Модель не хранит отдельные отрицательные утверждения.

| Код исходного факта | Смысл |
|---|---|
| likes_science | Интересуется наукой |
| likes_mystery | Любит расследования и загадки |
| likes_magic | Любит истории о магии |
| likes_adventure | Любит приключения |
| likes_philosophy | Любит философские вопросы |
| prefers_short | Предпочитает короткие произведения |
| prefers_classics | Предпочитает классику |

Промежуточные факты: genre_sf — подходит научная фантастика, genre_detective — подходит детектив, genre_fantasy — подходит фэнтези. Они появляются только после применения правил R01–R03.

| Код книги | Автор и название |
|---|---|
| solaris | Станислав Лем «Солярис» |
| martian | Энди Вейер «Марсианин» |
| orient_express | Агата Кристи «Убийство в Восточном экспрессе» |
| sherlock | Артур Конан Дойл «Приключения Шерлока Холмса» |
| earthsea | Урсула Ле Гуин «Волшебник Земноморья» |
| hobbit | Джон Р. Р. Толкин «Хоббит» |

Для каждой книги можно вывести факт candidate:код. Несколько таких фактов могут одновременно находиться в памяти: читателю могут подходить несколько книг. Окончательный выбор хранится отдельно от множества кандидатов.

Пример начальной памяти: W0 = {likes_science, likes_adventure}. В ней ещё нет genre_sf или candidate:martian. Система должна получить эти факты с помощью правил.

## 4 База продукционных правил

Продукция имеет вид «ЕСЛИ условия, ТО заключение». В таблице все перечисленные условия одного правила соединены логическим И. «НФ», «детектив» и «фэнтези» обозначают промежуточные факты из раздела 3. Заключение с кодом книги означает candidate:код.

| Правило | Условия ЕСЛИ | Заключение ТО | Приоритет |
|---|---|---|---|
| R01 | Интересуется наукой | НФ | 100 |
| R02 | Любит расследования | Детектив | 100 |
| R03 | Любит магию | Фэнтези | 100 |
| R04 | Подходит НФ | solaris | 40 |
| R05 | Подходит НФ И любит приключения | martian | 60 |
| R06 | Подходит НФ И любит философию | solaris | 60 |
| R07 | Подходит детектив | orient_express | 40 |
| R08 | Подходит детектив И предпочитает короткие произведения | sherlock | 60 |
| R09 | Подходит детектив И предпочитает короткие произведения И классику | sherlock | 60 |
| R10 | Подходит фэнтези | earthsea | 40 |
| R11 | Подходит фэнтези И любит приключения | hobbit | 60 |
| R12 | Подходит фэнтези И любит философию | earthsea | 60 |

Формальная запись R05: ЕСЛИ genre_sf И likes_adventure, ТО candidate:martian. Условия образуют антецедент правила, заключение является консеквентом. Правило применимо, когда оба условия уже доказаны.

R04 и R06 имеют одно заключение. Это два альтернативных способа доказать candidate:solaris. Для обратного вывода между такими правилами действует логическое ИЛИ: достаточно доказать условия хотя бы одного из них.

База использует положительные правила без переменных. Вывод только добавляет факты. Повторное добавление уже известного заключения исключается. Приоритет 100 у правил жанров позволяет сначала обработать применимые правила R01–R03. Для рекомендаций более детальные основания обычно имеют приоритет 60, общие основания — 40.

## 5 Прямой вывод

Прямой вывод начинается с известных фактов и ищет их следствия. Пусть W — текущая рабочая память. Конфликтное множество C(W) состоит из правил, все условия которых входят в W, а заключение ещё не входит в W.

```text
W := копия исходных фактов
повторять:
    C := все применимые правила с новым заключением
    если C пусто: вернуть W и протокол
    r := лучшее правило из C по стратегии конфликтов
    сохранить C и выбранное r в протокол
    добавить заключение r в W
```

За один шаг выполняется одно правило. После изменения памяти программа заново формирует конфликтное множество. Это позволяет учитывать правила, которые стали применимы благодаря новому факту.

Пример 1. Исходная память W0 = {likes_science, likes_adventure}.

| Шаг | Конфликтное множество в порядке выбора | Правило | Добавленный факт |
|---|---|---|---|
| 1 | R01 | R01 | genre_sf |
| 2 | R05, R04 | R05 | candidate:martian |
| 3 | R04 | R04 | candidate:solaris |
| 4 | Пусто | Остановка | Новых фактов нет |

Итоговая память содержит исходные факты и три новых факта. Кандидаты: «Марсианин» и «Солярис». Для одной итоговой рекомендации сравниваются их лучшие применимые обоснования: R05 имеет приоритет 60, R04 — 40. Выбрана книга «Марсианин».

Остановка происходит в неподвижной точке: ни одно правило не добавляет новый факт. Система не завершает вывод после первого кандидата, поскольку требуется сохранить все логические следствия и сравнить кандидатов после завершения.

Завершение гарантируется конечностью базы и запретом повторного добавления одного заключения. Здесь существует 9 различных заключений правил, поэтому выполняется не более 9 шагов с добавлением факта. В простой реализации каждый шаг просматривает все 12 правил.

## 6 Обратный вывод

Обратный вывод начинается с цели. Он ищет правило с нужным заключением, затем рекурсивно доказывает условия этого правила. Проверка запускается на исходных фактах независимо от результата прямого вывода.

```text
доказать(цель, путь):
    если цель есть в исходных фактах: вернуть доказательство
    если цель уже есть в текущем пути: эта ветвь неудачна
    для каждого правила с заключением цель:
        попытаться доказать все его условия
        если все доказаны: вернуть дерево доказательства
    вернуть отсутствие доказательства
```

Внутри правила требуется И: доказать все условия. Между альтернативными правилами действует ИЛИ: достаточно одного успешного правила. Неудача одной ветви не мешает проверить другие правила.

Для W0 = {likes_science, likes_adventure} цель candidate:martian доказывается следующим деревом. Отступ обозначает переход к подцели.

```text
candidate:martian [R05]
  genre_sf [R01]
    likes_science [исходный факт]
  likes_adventure [исходный факт]
```

Проверка на недостаточных данных: при W0 = {likes_science} можно доказать genre_sf, но likes_adventure отсутствует и не выводится правилами. Поэтому candidate:martian не доказан. Прямой вывод при этом рекомендует «Солярис» по R04.

Проверка альтернатив: для candidate:solaris сначала рассматривается R06. Если likes_philosophy не доказан, программа пробует R04. При наличии likes_science это правило успешно доказывает «Солярис».

Защита от циклов использует множество целей текущего пути. Повторная цель прекращает только текущую ветвь. Это сохраняет возможность найти доказательство через другое правило. Неудачные цели глобально не кешируются.

Ответ «цель не доказана» означает отсутствие доказательства из данной базы и данных. Он не устанавливает логическое отрицание цели. Обратный вывод проверяет, является ли книга кандидатом. Окончательное место книги среди других кандидатов определяется отдельно.

## 7 Разрешение конфликтов

Конфликт правил в этой работе означает одновременную применимость нескольких правил. Их заключения могут быть совместимыми. Для выбора следующего правила и итоговой рекомендации используется одинаковая последовательность критериев.

1. Выше числовой приоритет — правило лучше.
2. При равном приоритете больше условий — правило более специфично.
3. При полном равенстве выбирается правило, расположенное раньше в базе.

Ключ сортировки: K(r) = (−priority(r), −число_условий(r), позиция(r)). Выбирается минимальный ключ. Последний критерий делает результат воспроизводимым.

### Выбор по приоритету

В примере 1 после R01 применимы R05 и R04. У R05 приоритет 60, у R04 — 40. Поэтому первым срабатывает R05. После полного вывода оба кандидата остаются в памяти, но итоговая рекомендация выбирается по R05.

### Выбор по специфичности

В примере 3 заданы likes_mystery, prefers_short, prefers_classics. После R02 конфликтное множество имеет порядок R09, R08, R07. У R09 и R08 одинаковый приоритет 60. R09 содержит три условия, R08 — два, поэтому выбирается R09.

R09 и R08 выводят одну книгу. После срабатывания R09 заключение candidate:sherlock уже известно, поэтому R08 больше не добавляет новый факт. R07 затем выводит другого кандидата с меньшим приоритетом.

### Выбор по порядку

В примере 5 заданы likes_science, likes_magic, likes_adventure. После вывода жанров одновременно применимы R05 и R11. Оба имеют приоритет 60 и два условия. R05 расположен раньше, поэтому итоговая рекомендация — «Марсианин».

«Хоббит» также доказан как кандидат. Если поменять R05 и R11 местами, множество выведенных фактов сохранится, а итоговая рекомендация изменится на «Хоббит». Такой эффект проверяет отдельный тест.

Для положительных правил, добавляющих факты, стратегия управляет порядком выполнения, но полный прямой вывод сохраняет все достижимые следствия. Выбор единственной рекомендации представляет собой отдельное решение по тем же критериям. Запреты и противоречивые отрицательные факты в данной модели не рассматриваются.

## 8 Реализация средствами CLIPS

CLIPS выбран из числа инструментов, рассмотренных в третьей презентации. clipspy предоставляет Python-интерфейс к CLIPS. Версия зависимости в проекте зафиксирована: clipspy 1.0.6. Сопоставление фактов, формирование повестки и выполнение правил в этой версии выполняет CLIPS.

Правила прямого вывода CLIPS создаются функцией clips_constructs в main.py из общей базы RULES и загружаются в память через env.build. Отдельный файл правил для этого не требуется. У каждого правила есть уникальный salience, который кодирует место в общей сортировке. Больший salience соответствует более высокому месту. Например, у R09 значение 997, у R05 — 996, у R04 — 991.

Фрагмент R05 в CLIPS:

```lisp
(defrule R05
  (declare (salience 996))
  (known (value "genre_sf"))
  (known (value "likes_adventure"))
  (not (known (value "candidate:martian")))
  =>
  (assert (known (value "candidate:martian")))
  (assert (fired (rule "R05")
                 (added "candidate:martian"))))
```

Условие not здесь проверяет отсутствие уже выведенного факта и предотвращает повторное добавление. Оно не выражает запрет читать книгу.

Отдельные правила select-R04, select-R05 и другие выбирают одну книгу. Их salience отрицательный, поэтому они выполняются после всех правил вывода с положительным salience. У select-R05 значение −1004. Условие (not (selected)) позволяет сохранить только одну итоговую рекомендацию.

Программа создаёт Environment, создаёт правила через clips_constructs и env.build, выполняет reset, добавляет исходные факты через assert_fact и запускает run(1) по одному правилу. Перед шагом она читает настоящую повестку через activations(). Протокол CLIPS сравнивается с протоколом самостоятельного алгоритма.

Обратный вывод средствами CLIPS реализован отдельно в backward.clp: рекурсивная deffunction prove-goal проверяет исходные bc-known, ищет bc-rule с нужным заключением, доказывает все условия выбранного правила и пробует альтернативы при неудаче. Повтор цели в текущем пути останавливает ветвь. При успехе создаётся дерево bc-proof. Это явный алгоритм на языке CLIPS, а не встроенный режим обратного вывода.

Функция run_clips_backward создаёт отдельную среду, передаёт только исходные факты и правила и вызывает prove-goal через env.call. Python читает готовое дерево; алгоритмы forward и backward из main.py при этом не вызываются. Обе реализации обратного поиска независимо начинают с исходных фактов, без предварительного прямого вывода.

## 10 Автоматическая проверка и ограничения

С clipspy 1.0.6 выполнены 30 тестов. Все завершились успешно, без пропусков. Протокол записан в test_results.txt.

Полный перебор семи бинарных признаков содержит 2^7 = 128 профилей. Для каждого профиля сравниваются самостоятельный прямой вывод и CLIPS: факты памяти, конфликтные множества, порядок срабатывания и окончательный выбор с обоснованием.

Для каждой из шести книг на каждом профиле сравниваются прямой и обратный вывод Python: 128 × 6 = 768 сопоставлений. Ещё для всех 768 сочетаний сравниваются результаты и деревья обратного поиска Python и CLIPS. Проверяются циклы, альтернативные правила, пустой ввод и независимость CLIPS-поиска от Python-алгоритмов и предварительного прямого вывода.

| Проверка | Ожидаемое свойство |
|---|---|
| Приоритет | R05 выбирается раньше R04 |
| Специфичность | R09 выбирается раньше R08 |
| Равенство критериев | R05 раньше R11 в исходном порядке |
| Перестановка равных правил | Меняется победитель, сохраняется множество следствий |
| Неполные данные | Цель не доказывается без обязательного условия |
| Циклические правила | Поиск завершается и пробует альтернативы |
| CLIPS | Совпадают все результаты полного перебора |

Система обрабатывает одного читателя за запуск. Она использует положительные атомарные факты, не поддерживает удаление фактов, переменные, вероятности и логическое отрицание. Число условий применяется как упрощённая мера специфичности: для произвольных сложных логических формул такой критерий требует дополнительного анализа.

Прямой вывод сохраняет все достижимые заключения. При смене предпочтений выполняется новый запуск с новой памятью. Для промышленной системы понадобились бы более полный каталог, проверка правил специалистом и оценка качества рекомендаций на данных читателей.

Результат работы: разработана объяснимая система правил, реализованы оба направления вывода, задана воспроизводимая стратегия разрешения конфликтов и подтверждено совпадение самостоятельной реализации с CLIPS на всех профилях данной модели.

## 11 Запуск и состав проекта

Для самостоятельной реализации достаточно Python 3.10 или новее. Команды выполняются в папке 01_rules_practicum. Без установленного clipspy основной алгоритм работает, но 13 тестов фреймворка будут пропущены.

macOS и Linux, полный запуск:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install clipspy==1.0.6
python main.py --demo --framework
python main.py --test
```

В Windows можно создать окружение командой py -m venv .venv и далее использовать .venv\Scripts\python.exe вместо python без активации окружения. Первая установка зависимости требует доступа к интернету.

Для отдельного случая: python main.py --case 3 --framework. Для своих предпочтений: python main.py --interactive --goal martian. Для списка правил: python main.py --rules. Ключ --verbose показывает все попытки обратного доказательства.
